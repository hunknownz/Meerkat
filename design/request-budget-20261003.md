# 请求预算授权与结算实施合同

change_id：`meerkat-request-budget-20261003`。基线：`e48686050e822c04c590b53abecdaf48f45c8157`。独立工作区与分支沿用持久会话交付。

目标：把 Go / SQLite 的请求预留、发送、结算与未知结果接入 Pi 的真实模型请求入口。属于完整设计工作包 05、06、13、18 的请求部分。直接本地实现，不创建子 Agent，不提交付费模型请求，不切换主仓库或已安装服务。

## 合同

- 通用预算 Authority 与 Executor 分离。Go 决定策略，SQLite 是预算账本权威，Node 仅转换 Pi 请求协议。
- Run 预算绑定 Task、Session、冻结 Context / Profile / 合同、全任务 token 授权和本 Run 上限。初始每任务请求上限 256，单请求输出上限 8192；两者是明确版本化的默认策略，后续按实测校准。
- 同一短事务核对租约、Run / Session 活跃身份、合同、请求 ID、剩余额度后预留；网络与模型调用不进入事务。Task / Run 共用一份请求账本，不重复计量。
- 请求 ID 绑定输入摘要与预留参数。发送前取得一次性 begin 回执；重复 begin 不产生第二次发送许可。丢失回执不自动发送或重放。
- 完成按模型服务原始返回的实际用量结算，缺失字段保持未知。结果未知保留至少预留占用，重启或关闭时不自动释放。实际超出预留记录超额并阻止继续。
- token 预留使用明确的估算（请求 UTF-8 字节数加固定开销、受控最大输出），不宣称严格 tokenizer 上界。请求次数与截止时间在请求前硬限制；精确 token / 货币硬预算只有可靠上界和计价能力验证后才可声明。费用未知，不把 Pi 默认 0 或估算当账单。
- 首个可信桥接通道为 Pi 0.99.1 的 `openai-completions` HTTP 流。通过官方 Provider API 包装 SDK fetch；每个实际 HTTP 尝试单独预留，覆盖重试和压缩。未验证的 API / WebSocket / 非文本输入拒绝通过此桥，不能绕过到未受控传输。
- 显式加载打包进 Go 的可信扩展，保持个人 / 项目扩展发现关闭。私有 Unix socket 与随机 Run 凭证用于预算通信；不向公开事件、快照、MCP、日志或进程参数输出 payload、凭据或控制令牌。
- 先验证桥接 ready，再发送任务 prompt。RPC 历史与预算结果分别核对。预算结果未知保留 Task / Run 未知，不生成成功交付。
- SQLite V5 自动升级并保留 V1–V4 历史；备份核对账本绑定、索引、状态与摘要。原历史 Run 用量单独计入，不能与请求明细重复计算。

## 必验

并发预留不超分配；Task / Run 共同限额；自动降低输出上限；重复 ID 与参数冲突；一次性 begin 和丢失回执；部分/未知用量与超额；租约丢失、合同更改、截止时间和重启；升级、备份恢复与损坏拒绝；私有协议脱敏。

真实安装的 Pi 使用隔离配置及本地假模型 HTTP 服务，验证请求在网络之前被授权、原始 SSE 用量被结算、下一请求被拒绝、历史及报告不会误算。该服务不使用真实模型密钥或账单。预算软收尾、阶段预留和脏工作区检查点恢复仍是后续工作，不能由本项替代。

参考：[Pi Provider 扩展](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/custom-provider.md)、[Pi 扩展合同](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)，同时核对本机 0.99.1 的 SDK `fetch`、`maxRetries` 和 Provider 实现。

## 联调发现与处理

- Pi 的原生 `.mjs` 动态 import 无法从临时目录解析全局 CLI 包。改为打包 TypeScript 薄入口，使用 Pi 官方加载器的包别名取得真实版本，再调用无外部依赖的 HTTP 桥。
- 首轮额度拒绝测试约 14.9 秒结束，原因是 Pi 的自动重试等待。增加私有停止通知，Go 在拒绝或未知结算时立即清队列、abort 和核对 idle；第二轮拒绝测试约 1 秒结束。
- 请求账本接管 Run 用量，包含没有请求记录的运行，防止重新落回 SDK 规范化计数或费用。未知字段不填零。
