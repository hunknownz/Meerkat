# 持久异步分发实施合同

日期：2026-10-03。change_id：`meerkat-async-dispatch-20261003`。

本工作包属于 [整体重构](session-budget-coordination-20261003.md) 的调度与控制部分。后续仍需完成 Pi 会话、预算收尾、检查点、恢复、完整交付、Issue、界面和实际安装验证；本工作包完成不等于整体完成。

目标：主 Agent 可以快速提交冻结任务，获得持久 Operation ID。所有分发共用 Go 调度器；不同工作区可并行，相同工作区排他，依赖必须有已核对且可用的交付版本。

范围：SQLite 操作/成员表及迁移、Go 调度与兼容调用、私有 Socket、CLI、MCP 分发/查询/有限等待、相应检查和文档。独立 linked Worktree，本地直接实现；不创建子 Agent、不调用付费模型、不改用户的运行服务或安装版本。

## 合同

- 控制请求 ID 与 Operation/Task/Run ID 分开。请求 ID 和保留任务顺序的输入摘要在 SQLite 唯一绑定；相同输入返回原操作，异参拒绝。回执丢失不自动重发。
- 提交先检查范围、任务、Context、Profile、依赖、状态与进程事实。短事务核对冻结摘要、取得任务占用、保存 Operation 和排队成员后才确认接受。Git、模型和网络操作在事务外。
- 一个调度循环拥有所有并行执行，兼容 `execute`/`run` 的等待式调用。保留旧等待式入口的忙碌语义；新的异步入口允许提交独立任务。并行上限适用于所有分发之和。
- 同一 Task 不能重复排队或运行。同一 Worktree 同时只启动一个任务；依赖等待属于排队时间，不作为模型执行时间。
- 排队时冻结 Task 的目标、范围、验收、Context、Profiles、基准、依赖和预算摘要；开始前再次核对。后续默认 Profile 更改不替换该任务的冻结 Profile。当前原始任务预算保持有效。
- Operation 的“已完成”表示本次所有成员都取得结果，不意味着代码交付通过；每个成员保留实际 Task 状态、候选 SHA、原因与恢复角色。
- 客户端退出/取消等待不停止执行。有限等待超时返回仍在运行的 Operation；显式停止仍按 Run 的停止回执。
- 进程开始前持久标记成员已开始。服务重启后，曾开始且未确认结算的 Operation 标为未知，不自动重放；原始 Task/Run 的不确定身份和修改保留。只从未开始的队列恢复，并再次核对冻结合同。
- 优雅关闭等待已拥有的执行退出；未开始的队列保留。租约丢失后禁止继续写入和启动执行。
- 迁移、备份和恢复保留操作与去重信息，旧版备份仍可读取并升级。公开操作不包含提示词、私有路径、环境变量或写令牌。

## 验收

立即接受和持久句柄；跨请求全局并发；相同工作区排他；任务占用、依赖等待及失败；幂等/异参冲突；冻结字段变化拒绝；MCP/CLI/Socket 回执和等待超时；断开不停止；已开始操作重启为未知、未开始队列安全恢复；关闭与租约失效；V1/V2 到新 schema 的幂等升级、备份恢复、历史和用量保持。

状态：本地实现与隔离验证完成；尚未集成主仓库、替换安装版本或发布。

## 实现与证据

- SQLite V3 保存 Operation、成员与任务唯一占用；去重匹配信息保留在备份与恢复中。V1/V2 历史迁移与未知用量对账通过。
- Go 全局调度循环接替旧批次调度；旧 `execute` / `run` 通过提交与等待复用同一队列。任务提交顺序是合同的一部分。
- CLI 增加 `dispatch`、`operation`；Socket 增加 `dispatch`、`operation`、`wait-operation`；MCP 增加 `dispatch_tasks`、`get_operation`、`wait_operation`。
- 持久化先于接受回执；丢失回执可用 requestId 找回。客户端取消等待和连接关闭不取消执行。
- 已开始且未取得结果的操作重启后为未知；从未开始的队列保留。没有加入自动重放、仅凭旧 PID 停止或脏工作区恢复。
- 覆盖跨请求全局并发、同 Worktree 排他、同 Task 占用、依赖失败、合同变化、冻结 Profile、回执去重/冲突、等待取消、关闭、租约失效、重启、备份和私有字段脱敏。
- 真实私有 Socket 验证丢失首个回执、按 requestId 找回、等待超时和显式停止；使用本地假执行器，未调用付费模型。
- 本轮新增实现及检查未运行编码子 Agent。实际 Codex token 与费用无法从这些本地测试测得，保持未知，不填为零。
