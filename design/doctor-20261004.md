# Read-only doctor diagnostics

Date: 2026-10-04. Baseline: `d77ae2e63f9b3b2c0343a2f05cdbd73fce25551d`.

Goal: explain local installation, service, database, session-state and request
budget problems before a coding run. This is work package 19 of the session and
budget plan; a successful report is not paid-run or native UI acceptance.

Scope: versioned CLI JSON diagnostics; true read-only SQLite inspection without
opening the migrating writer; bounded private socket health/version checks;
optional private Profile validation and adapter-owned Pi compatibility checks;
tests, install documentation, a beta.7 runtime/plugin install and authorized push.
Use the clean linked `codex/rpc-session-foundation-20261003` worktree. No database
schema change, paid calls, subagents or remote Issue writes.

Context: preserve the existing doctor envelope and common fields. Checks report
ok, warning, blocked or not_checked with fixed messages and concrete next steps.
Unsupported/corrupt/unsafe state blocks; absent installation or stopped service
warns. Unknown sessions, requests, controls or Runs remain unknown and block
continuation of affected work. Historical pending records are not replayed.

Profile: no model execution profile is used for this implementation. An optional
`--profile` reads one explicitly selected private config through the same frozen
Profile validation as prepare. The executor adapter owns provider/API and protocol
compatibility diagnosis. Default inspection never launches a CLI or reads keys.
`--probe-executor` requires that profile and runs only the resolved executable's
version command in an isolated temporary directory with no inherited secrets.
It does not pass model/task/session flags or load the configured agent directory.
No model prompt, credential test or provider HTTP request is made.

SQLite inspection validates privacy, supported schema, integrity, foreign keys
and aggregate lifecycle states in a bounded read transaction. Missing older-schema
evidence stays null. It never migrates, acquires a controller lease, repairs,
changes permissions or signals a PID. Session diagnostics describe stored states;
history/contract identity is still verified by execution and explicit recovery.
Static endpoint/API and compatible version evidence never become an actual budget
gate readiness claim; that handshake is verified before each model prompt.

Acceptance: empty/missing directories remain untouched; old/future/corrupt stores
are not migrated; live WAL records are visible; permissions and foreign-key
failures block; unknown and unavailable evidence stay distinct; service version
mismatch and malformed/stalled replies do not pass; private profile, unsupported
executor/API, missing/incompatible CLI and bounded probe failures are diagnosed;
raw errors, transcripts and credential values never enter output. Installed
diagnostics and history reconciliation complete the local handoff. Paid Pi and
changed native detail acceptance remain pending separately.
